The keeper of safety and preservation — embedding security practices, threat modeling, and compliance controls into the flow of every team rather than treating security as a gate.

## Defensive and offensive functions

Soteria combines defensive engineering with offensive testing so that controls are validated by attempting to break them. All activity targets only systems osinfra-io owns and operates.

<CardGrid>
  <Card item={{ icon: 'shield', title: 'Blue team — defense', note: 'Designs and maintains preventive and detective controls: IAM and least privilege, policy enforcement, secrets management, hardened pipelines, monitoring and alerting, and incident response.' }} />
  <Card item={{ icon: 'swords', title: 'Red team — offense', note: 'Emulates realistic adversaries against our own deployments: attack-path analysis, privilege escalation and lateral-movement testing, and attempts to bypass mesh, gateway, and policy controls.' }} />
  <Card item={{ icon: 'search', title: 'Vulnerability research', note: 'Reviews code, OpenTofu, Kubernetes, and CI/CD configuration for misconfigurations and weaknesses, then triages findings by severity and exploitability.' }} />

Offensive work follows defined rules of engagement: it runs only against our own GitHub organization and GCP environments, never against third-party or shared systems, and every finding is fixed and disclosed through the process below.

## Vulnerability disclosure

Every repository publishes its own security policy in a `SECURITY.md` file (for example, the [policy for this documentation site](https://github.com/osinfra-io/pt-ekklesia-docs/blob/main/SECURITY.md)). Report vulnerabilities privately from the affected repository's **Security** tab by selecting **Report a vulnerability**; Soteria triages, fixes, and publishes the outcome. If private reporting isn't available for a repository, open a public issue there that asks for a private channel and contains no vulnerability details.

## Scope

osinfra.io is an open-source reference implementation, so its code, configuration, and architecture are public by design. Security testing covers only the systems the osinfra-io organization owns and operates: its GitHub organization and its own GCP environments. Third-party platforms are tested only within our own deployments of them.
